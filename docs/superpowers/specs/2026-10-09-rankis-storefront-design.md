# rankis.lt — новая витрина (этап 1)

Дата: 2026-10-09. Статус: утверждено пользователем в чате.

## Цель

Новый сайт rankis.lt с обновлённым дизайном, на собственной платформе (React + Node).
Этап 1 — только витрина на реальных данных текущего магазина. Бэкенд, оформление заказа,
оплата, доставка, админка и импорт прайсов — следующие этапы, не входят в этот документ.

## Ограничения и решения

- Стек: Next.js 16 (App Router, последняя стабильная), TypeScript, Tailwind CSS. Без UI-библиотек.
- Папка: `C:\Users\MaksimNosovičTeronis\rankis-next`, свой git-репозиторий.
- Данные: JSON-файлы в `data/`, собранные скриптом с текущего rankis.lt. Verskis API
  даёт только PATCH, поэтому источник — публичные страницы: `menu.xml` (категории) и
  JSON-LD на карточках товаров (`products.xml?offset=N&limit=2000`, ~122 тыс. URL).
- Объём данных: срез ~3000 товаров, равномерно по верхним категориям. Полный импорт —
  этап «бэкенд».
- Картинки: ссылки на `rankis.lt/images/...`, не скачиваем. `next.config` разрешает
  этот хост для `next/image`.
- Бренд: жёлтый + чёрный сохраняем, подача современная.
- Язык интерфейса: литовский (как у текущего сайта). Тексты UI — в одном файле
  `lib/ui-text.ts`, чтобы потом добавить RU/EN.

## Данные

### Скрипт `scripts/scrape.ts` (запуск `npm run scrape`)

1. Качает `https://www.rankis.lt/menu.xml`, строит дерево категорий по URL-путям
   (`/detales111/a/b/c` → slug `a/b/c`, родитель `a/b`). Имя категории берётся из
   хлебных крошек товаров (JSON-LD BreadcrumbList), для категорий без товаров — из
   последнего сегмента slug с заменой дефисов.
2. Качает первые N чанков `products.xml`, берёт список URL товаров.
3. Для каждого URL (параллельность 6, задержка, User-Agent браузера, ретрай при 429/5xx)
   парсит страницу: JSON-LD `Product` (name, sku, brand, image, description, offers.price,
   availability) и `BreadcrumbList` (путь категории), плюс из HTML: старую цену (если есть),
   все картинки галереи, таблицу характеристик (пары «имя: значение»).
4. Останавливается, набрав ~3000 товаров, при этом не более ~150 на одну подкатегорию
   третьего уровня, чтобы срез был разнообразным.
5. Пишет `data/categories.json` и `data/products.json`. Инкрементально: уже
   скачанные товары не перекачивает (кеш в `data/.cache/`).
6. В конце — проверка целостности (падает с ненулевым кодом, если нарушено): у каждого
   товара есть slug, name, price > 0, image, categoryPath, и путь существует в дереве.

### Типы (`lib/types.ts`)

```ts
type Category = { slug: string; name: string; parent: string | null; image?: string };
type Product = {
  slug: string; sku: string; name: string; brand: string;
  price: number; oldPrice?: number; inStock: boolean;
  images: string[]; description: string;
  specs: { name: string; value: string }[];
  categoryPath: string[]; // slugs от верхней категории к листу
};
```

### Слой доступа `lib/catalog.ts`

Единственное место, которое читает JSON. Функции: `getCategoryTree()`, `getCategory(slug)`,
`getChildren(slug)`, `listProducts({ category, brand[], minPrice, maxPrice, inStock, sort, page, perPage })`,
`getProduct(slug)`, `searchProducts(q)`, `getRelated(product)`, `getBrands(category)`,
`getPromoProducts()` (есть oldPrice), `getNewProducts()` (последние по порядку в файле).
На этапе «бэкенд» заменяется на запросы к БД без изменения страниц.

## Страницы и маршруты

| Маршрут | Содержимое |
|---|---|
| `/` | Шапка, промо-блок, плитка верхних категорий, полоса брендов, лента «Akcijos», лента «Naujienos», футер |
| `/c/[...slug]` | Крошки, заголовок, подкатегории чипсами, фильтры (бренд, цена, в наличии), сортировка (популярные/дешевле/дороже/название), сетка карточек 4×, пагинация по 24 |
| `/p/[slug]` | Галерея, бренд, название, код, цена/старая цена/бейдж скидки, наличие, кол-во + «Į krepšelį», характеристики, описание, «Panašios prekės» (8 из той же листовой категории) |
| `/search?q=` | Та же сетка карточек, поиск по name и sku (без регистра, по словам) |
| `/cart` | Таблица позиций, +/−, удалить, сумма, кнопка «Pirkti» → `/checkout` |
| `/checkout` | Заглушка «Užsakymų priėmimas ruošiamas» с телефоном и e-mail |
| `/[static]` | Pristatymas, Garantija, Kontaktai — статичные страницы с текстом-заглушкой |

Фильтры и сортировка — через query-параметры (`?brand=a,b&min=&max=&stock=1&sort=&page=`),
страницы серверные. Карточка товара и категории статически генерируются при сборке.

## Компоненты

- `Header` — липкий. Лого, широкий поиск, телефон + e-mail, иконка корзины со счётчиком.
  Под ним чёрная полоса `CategoryNav` с верхними категориями; при наведении —
  выпадающий блок с подкатегориями двух уровней.
- `MobileBar` — нижняя панель на мобильных: Katalogas (открывает дерево), Paieška, Krepšelis.
- `ProductCard` — фото, бренд, название (2 строки), код, цена, старая цена, бейдж «-N%»,
  точка наличия, кнопка «Į krepšelį» (на десктопе появляется при наведении, на мобильном всегда).
- `ProductGrid`, `Filters`, `SortSelect`, `Pagination`, `Breadcrumbs`, `Price`, `Badge`,
  `Button`, `QuantityInput`, `Gallery`, `SpecsTable`, `Footer`.
- `CartProvider` — React context, состояние в `localStorage` (`rankis-cart`), API:
  `add(slug, qty)`, `remove`, `setQty`, `total`, `count`.

## Обработка ошибок

- Нет товара/категории → `notFound()` и своя страница 404 с поиском.
- Пустой результат фильтра/поиска → блок «Nieko nerasta» с кнопкой сброса фильтров.
- Битая картинка → `onError` ставит серый плейсхолдер.
- Скрипт сбора: ошибки сети логирует и пропускает URL, не падает; падает только проверка целостности.
